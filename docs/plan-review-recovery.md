# 方案审核不确定与确认空转修复

## 问题与行为

Agent 已写出具体方案，但后置 Jev 分类低于阈值时，旧实现将 `SemanticUncertain` 直接记为 `needs_information`。界面隐藏确认按钮且无法重试；随后用户发送确认，轻量路由只寻找 ready 方案，于是又生成一轮讨论。Agent 提前承诺按钮可用，进一步造成正文与真实状态矛盾。

修复采用通用方案审核与确认逻辑，不匹配任何项目 ID、提示词片段或媒体业务 case：

- `plan_review_context.build()` 传入当前需求、完整度受限的方案与近期历史、当前项目素材，以及已保存工作区/共享文件的逻辑引用、哈希和大小。范围与截断显式记录；已保存不代表内容已检查或质量已通过。原始文件内容不下载到审核入口。
- Jev 原有阈值不降低。低置信度、协议错误或服务异常时，最多进行一次独立模型复核；明确返回缺信息但没有具体缺失项时也需要复核。复核要求结构化四项检查、置信度、公开理由及缺失项。
- `uncertain` 表示无法确定，`unavailable` 表示检查服务失败，`needs_information` 必须有可向用户说明的具体缺失项。它们都不授权执行；支持绑定 digest/项目内容的两次人工重试。历史笼统缺信息记录也可重新检查。
- 确认处理共用于轻量入口和非轻量 Harness 的初次路由。用户确认未通过审核的原方案时，仅保存原方案关联并解释阻塞，不重复登记执行意图。重新检查通过后仍须再次确认，旧确认不会自动执行。
- 更改需求、所选输入、内容指纹、新方案声明、取消或审核期间出现未关联的新对话，不能被迟到审核覆盖。重复确认沿用现有原子消费；切换 Harness 不绕过方案门禁。
- Agent 提示改为提交方案等待服务端检查。页面按服务端状态显示确认入口、具体补充项和“重新检查方案”，不依赖 Agent 的文字承诺。

## 诊断与计量

每次成功应用审核结果时，保存 `agent_events.kind=plan_review`：方案 digest、输入摘要哈希、覆盖范围、保存文件数量、历史引用以及审核分数/来源。不会将完整提示词或输入正文复制到遥测。

任务诊断增加 `plan_readiness` 和最近三次 `plan_reviews`，投影状态、摘要、分数、阈值、来源和四项检查；不输出模型自由文本理由或原始方案。Jev 与独立复核分别进入原有模型账本；分类不确定可同时表现为 HTTP 调用成功和 `SemanticUncertain`，不代表方案通过。

## 验证入口与边界

- `tests/test_plan_review_recovery.py`：不确定状态、同方案重试、确认不自动执行、需求变化、迟到结果、重复/有界重试、输入证据、独立复核与安全诊断。
- `tests/plan_readiness.test.mjs`：状态提示与确认入口。
- `tests/campaign_plan_review_browser.py` / `.cjs`：隔离真实 PostgreSQL、Redis、双 API 与 Chromium。分类结果采用协议夹具，核对自然确认阻塞、重试、刷新、窄屏、再次确认、重复及越权拒绝；不声称执行真实媒体。
- 真实模型验证另使用独立数据库，复查原始不确定输入、补齐保存文件证据的输入、历史确认跟进、确实缺素材与问候。用户项目状态不由测试夹具修改。

完整回归、真实服务结果、当前部署指纹及用户项目重新检查结果见本轮交付报告。模型分数不是校准后的正确率，不据单个高分宣布所有自然语言分类都可靠。复核不确定时仍保留明确状态和恢复路径。

## Jev 全入口上下文审查

当前只有两处 HTTP 调用实现、三类语义判断：`semantic_review.classify(plan)`、`semantic_review.classify(confirmation)`、`ControlIntentClassifier.resolve()`。重新规划是控制分类的 replan 结果，不是额外的模型入口；workflow 的结构化用户决策不调用 Jev。

| 判定 | 原输入边界 | 本轮调整 |
| --- | --- | --- |
| 方案就绪 | 当前消息、当前回复、意图、上传素材和历史交付名；缺已有缓存/工作文件及关联原方案 | 加入项目保存文件与近期原文历史、覆盖范围；不确定与确实缺信息分开 |
| 自然语言确认 | 当前消息、候选方案及意图；只选择 ready 候选 | 关联最新方案，即使待检查也能解释阻塞；增加原请求、审核状态、选中素材及画布目标 |
| 查询/暂停/恢复/取消/重新规划 | 当前消息和 task_status；没有目标方案或待决问题 | 加入服务端选定任务的已确认方案、公开回复、步骤目标/修订、待回答问题与选项；不取其他项目或未关联工作流 |

控制判定只解释本次消息，不把历史命令当新指令，不把决策选项或额外生成批准当作任务恢复。缺上下文或分类不确定仍返回未识别，保留任务；没有加入自动二次模型执行控制。明确按钮和固定口令仍不依赖模型。

模型返回后，在原子控制事务中核对目标仍活动，以及方案、步骤修订和待回答问题的 binding_digest 未变化。普通进度推进不改变语义绑定；修订或问题变化时拒绝迟到操作，不能将它应用到更新后的任务。每次模型分类保存绑定摘要与分数，任务诊断提供 `control_classifications`，不复制用户文本或完整任务上下文。
