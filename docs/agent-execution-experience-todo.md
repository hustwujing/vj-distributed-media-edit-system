# Agent 执行展示、流式输出与消耗优化待办

记录日期：2026-11-01。状态：实现、测试、部署与验证完成，最终版本 da2708afd505；结果与边界见 [完整报告](agent-execution-experience-report.md)。

依据：[项目排查报告](project-a41ef32a-investigation.md)。本清单整合本次项目排查与后续修复讨论，作为后续实施入口；不把之前版本的测试通过视为这些新增问题已解决。

## 已确认的事实与边界

- 目标项目只有一轮 plan 任务：轻量入口接管一次沙盒执行，完成素材检查和静态预览，没有正式视频交付或持久化 workflow。
- 25 次模型请求、29 次工具调用及已回报 Token 与保存的证据一致。Jev 超时的一次请求仍未知，不能算零消耗；没有供应商账单对账结论。
- 正文终态覆盖、当前状态回退旧说明已重放复现；网关尾部缓冲延迟完整 SSE 事件已受控复现。
- 本轮只有 2 条 Agent 公开过程说明。工具工作期间没有正文不一定是传输故障，不能编造说明或展示内部推理来填补。
- 约 8 分 17 秒的规划偏重，需要限制预览和自检范围。不能因任务看起来复杂就跳过用户确认，自动执行正式工作流。

## T1：网关流式输出

主要涉及 `agent_gateway.py`、`light_conversation.py`、`egress_policy.py`。

- [x] 替换固定最长敏感值长度的无差别尾部保留；只暂留可能构成敏感值前缀的内容，匹配排除后及时释放。
- [x] 设计统一增量检查器，覆盖原始传输与 JSON 解码后的逻辑文本；敏感值拆在多个 delta、多个网络块或 JSON 转义中仍可识别。
- [x] 安全且完整的 SSE 事件及时转发；不能为 flush 生成非法 JSON、截断 UTF-8，或改坏 SDK 使用的协议结构。
- [x] 完成事件中重复携带的全文、错误内容和其他可见字段遵循同一检查规则，不能从另一条路径泄漏。
- [x] 检查轻量回复路径的固定文本尾部保留，复用通用规则，避免只修复沙盒路径。
- [x] 验证读取 API 在 chunked 与非 chunked、稀疏输出下的行为，避免为了凑足读取长度继续等待。
- [x] 检查器有内存和事件大小上限；取消、断流、失败时正确收尾。不能用超时无条件释放未判定安全的前缀，也不能单凭 SSE 帧边界放弃跨 delta 检查。

验收：受控上游发出完整安全句子后停顿 3 秒，浏览器须在停顿期间显示完整句子，测试环境目标 1 秒内；同时跨块、跨事件、转义的敏感值拦截测试通过。真实链路单独测量，不把受控测试时延当作线上保证。

## T2：正文消息持久化

主要涉及 `agent_host.py`、`agent_text.py`、`agent_store.py`、`agent_api.py`、`text_stream.js`、`chat.js`。

- [x] 定义公开消息记录，包含任务、执行尝试、代次、消息 ID、公开阶段、顺序、文本版本和完成状态；不持久化内部推理正文。
- [x] 过程说明与最终答复独立保存，终态追加或确认最后一条消息，不覆盖已完成的过程消息。
- [x] 增量、快照、数据库恢复使用同一消息身份与版本规则；Redis 仅作实时通道，不能成为唯一历史来源。
- [x] 轻量升级到沙盒、工作流验收续跑和新的执行尝试保留此前公开过程，并标明阶段边界。
- [x] 重复/迟到事件幂等处理；缺失增量自动补齐。失败、取消的未完成回复明确标记，不伪装为完整答复。
- [x] UI 可折叠过程，但结束、刷新、重新打开页面后仍可查看。最终答复单独用于方案判断与交付解释，避免把历史过程混入授权依据。
- [x] 明确存量任务的恢复边界：仅从现有公开记录恢复，不编造没有持久化的消息。

验收：三段公开消息在运行、结束、刷新、断线恢复和续跑后保持顺序、内容完整且不重复；覆盖成功、失败和取消，不能再次出现 675 字符被最终 466 字符替换的问题。

## T3：当前执行状态

主要涉及 `live_activity.py`、`agent_activity.py`、`work_status.js`、`activity.js`、`chat.js`。

- [x] 当前状态仅来自尚未结束的活动；删除用最后一条 note 充当当前工作的回退逻辑。
- [x] 活动具备稳定身份、尝试/代次、事件顺序、开始与结束生命周期；旧尝试不能覆盖新尝试，迟到开始不能复活已结束活动。
- [x] 上一活动结束而下一活动未上报时显示衔接状态；连接失效时显示状态可能过期及最后更新时间。
- [x] 长时间没有内容不能直接判断执行卡住，结合传输连接、执行器心跳、租约与实际超时状态判断。
- [x] 区分模型请求等待、模型公开协议阶段、工具运行、宿主操作和外部任务等待；阶段名称不得声称知道模型具体思考内容。
- [x] 真正并发的活动并列展示，不简单用“最后一条”覆盖其他执行主体。
- [x] 重连以服务端当前活动集合校准，再接收增量；结束的尝试不残留运行中状态。
- [x] 同一绘制帧内连续更新合并，减少瞬时闪动；不能靠人为延迟掩盖真实状态。

验收：覆盖活动空档、快速交替、并发、乱序、旧代次、重连、租约失效及终态。历史说明不再出现在“当前执行”位置。

## T4：执行说明与历史

- [x] 区分 Agent 公开过程说明、系统阶段事件、工具步骤和最终答复；说明区不是完整日志时明确其范围。
- [x] 公开过程消息按 T2 的消息身份逐步展示，完成后保存；不能等整轮结束才补齐。
- [x] 采用身份去重，不以文本相同为由删除不同阶段确实发生的说明。
- [x] 补齐活动历史分页、断线恢复、Redis 过期、加载失败重试和加载完成标记；避免部分回放后被误认为已加载全部历史。
- [x] 关键系统阶段提供程序化事实，如准备环境、保存成果、验收；不为了凑文字额外调用模型，不编造执行进度。

验收：原任务可恢复 29 项工具、2 条公开说明和3条系统进度；同文不同身份可共存，重复投递同一身份只展示一次。

## T6：消耗统计与解释

- [x] 将标签解释为持久化工作流步骤、外部生成业务服务、已回报 Token；注明查询/收取不涵盖所有网络传输。
- [x] 分开展示任务/需求范围、调度尝试、实际沙盒实例、模型请求、Agent 工具和工作流步骤，避免把调用次数当沙盒数量。
- [x] 模型明细展示用途（轻量入口、沙盒 Agent、方案检查等）、状态、耗时、回执是否存在；未知与失败区分。
- [x] 工具失败可关联具体错误与后续纠正调用；Agent 自行改命令不能冒充工作流重试，无法可靠关联时不得推算重试次数。
- [x] Token 保留已知值与缺失次数；明确缓存命中是输入子集、推理是输出子集，重复上下文按请求累计，不重复加总子集。
- [x] 存储上传/下载等已有阶段指标单独展示，CPU/GPU 尚未采集时保持未采集，不以零表示。
- [x] 加入逐次及聚合一致性检查：调用去重、响应去重、回执冲突、总量算术、子集边界、当前任务/关联需求范围和失败/取消/续跑场景。

验收：本次项目所有指标有可追溯依据；另选择真实包含 workflow、业务服务提交/查询/收取和步骤重试的任务，验证非零指标，不能只用本轮的零值验证统计正确。

## T7：规划预算与工作流边界

- [x] 为规划预览定义可配置的时间、模型/工具调用、预览次数和自检次数预算，使用通用任务条件，不匹配特定案例文字。
- [x] 明确停止条件：输入和关键参数足以确定、必要预览已展示、验收条件已登记后返回方案；只有具体问题才追加检查。
- [x] 预算达到时如实说明已完成内容、未解决问题及下一步；不能伪装成功或继续无限自检。
- [x] 规划只做决策所需的少量分析与预览，正式编辑及昂贵生成遵守确认边界。需要重型前置操作时显式设计授权和受控执行路径，不偷偷扩张 plan 权限。
- [x] 已确认多阶段任务中，受支持的图片/视频/媒体操作通过工作流节点编排；直接工具用于独立短小处理。提示词、能力说明和提交校验共同落实，不能只依赖一句提示词。
- [x] 外部模型/特殊环境操作走受控执行器；脚本不绕过任务记录、权限、取消、恢复和用量管理。
- [x] UI 区分规划预览、待确认方案、正式执行与最终交付，并解释为何当前 workflow 步骤数为零。

验收：用多种素材和表达完成“分析预览—确认—正式处理—验收”，确认前无正式交付或未授权收费操作；确认后多阶段正式处理确实形成持久化步骤，并验证中断恢复。

## T8：Jev 检查超时

实施中发现：Jev 独立小请求等待 30 秒仍未返回，上游同期请求日志显示约 500 秒耗时。本系统不修改其他开发任务使用的 Jev 服务。新增一次主模型结构化方案检查作为网络故障兜底：要求四项完整性证据均为真且置信度至少 0.95 才能给出 ready，两次请求分别记录用量；自然语言确认识别不走此兜底，实际执行仍须明确确认并校验方案版本。

- [x] 排查本轮约5秒超时，核实服务耗时、超时配置、取消和既有方案判定兜底；不能直接用提高超时掩盖问题。
- [x] 将检查成功、检查不可用、缺少信息与普通讨论分别展示，检查超时不能显示为检查通过。
- [x] 保留已生成的方案与预览；重试检查复用同一方案版本，执行授权仍绑定明确的最新方案。
- [x] 若提供重试，必须有界并可追踪；每次真实请求独立计数，原未知回执不能被新结果抹掉，不默认后台无界重试。
- [x] 覆盖用户自然语言确认路径，检查失败不能自动授予执行权限；既有结构化兜底与模型判定的依据应可解释。
