# 讨论阶段发送样式预览图

用户要求「先把样式给我看」「发张图片」「做两个方案对比」时，先制作实际预览图，再讨论。
这属于已请求的样式讨论，不需要先点击“确认方案并执行”。正式成片、新转写和修改剪辑计划仍按原流程确认。

## 网页如何收到图片

每轮消息给出一个可写目录：`<workspace>/edit/previews/<turn_id>/`。
把本轮要展示的静态 PNG/JPEG/WebP 保存到**这个目录**。可以在里面创建必要的临时脚本，但只有验证通过的图片会交付。
结束本轮后，服务器在项目隔离环境中解码检查图片，再复制到当前轮次的私有结果区；聊天会显示可点击放大的缩略图。

- `view_image` 用于 Agent 自查，不会自动把图片送到网页。
- `/tmp` 中的抽帧不会自动交付。调试帧可放 `/tmp`，最终样式图须放指定预览目录。
- 原素材、已有正式剪辑和以前轮次的预览保持只读。之前的预览可以在 `edit/previews` 下按轮次查阅。
- 不要把工作区改为全部可写来绕过限制，也不要让用户先确认生成成片才能看图片。
- 每轮最多交付 12 张图，每张最多 32 MiB、2000 万像素，总计最多 128 MiB；不交付 SVG、动画图片、伪装图片、链接或管道。

回复中说明这是样式预览，并列出字号、颜色、位置等主要区别。可以引用图片：

```markdown
方案 A：白字，底部半透明背景。

![方案 A](edit/previews/实际轮次ID/style-a.png)
```

路径必须对应真实生成的本轮文件。网页将引用关联到私有图片，不应只展示一个不可访问的服务器路径。

## 使用辅助脚本

在当前工作区运行。脚本路径相对于 Skill；网页中固定为 `/opt/video-use/helpers/preview_style.py`。
将示例中的素材路径和预览目录换成 `assets.json` 与当前轮次消息给出的实际值。

```bash
python /opt/video-use/helpers/preview_style.py \
  --input sources/素材文件.mp4 --time 1.5 \
  --text '寻找旅伴' --font-size 48 --color '#FFFFFF' --position bottom \
  --width 720 --height 1280 --fit blur \
  -o edit/previews/实际轮次ID/style-a.png
```

可用参数：

| 参数 | 含义 |
| --- | --- |
| `--input` | 本项目视频路径；省略时使用纯色背景，可在无素材时先讨论文字样式 |
| `--time` | 取哪一秒的原片，默认 0，必须在素材范围内 |
| `--text` | 标题，支持中文与换行，最多 500 字 |
| `--font-size` | 默认 48，10–200 |
| `--color` | #RRGGBB，默认白色 |
| `--position` | top、center、bottom，默认 bottom |
| `--no-box` | 不加半透明标题背景 |
| `--width/--height` | 默认 1280×720；64–4096 的偶数 |
| `--fit` | contain 完整保留并留黑边、cover 居中裁满、blur 完整主体加模糊背景 |
| `--workspace` | 默认当前 cwd；输入与输出都必须属于这个工作区 |
| `-o` | 必填，指定本轮预览目录中的新 PNG 文件名，不覆盖已有图片 |

标题排版和中文字库与 `edit_media.py` 共用，便于确认后制作一致的成片。
其他复杂样式可以自行用 Pillow/FFmpeg 制作；仍保存到当前轮次的预览目录。制作 1–3 张清楚的对比图通常足够。
Agent 应先查看实际生成的图片，修正方框字、遮挡和布局错误，再向用户说明方案。
