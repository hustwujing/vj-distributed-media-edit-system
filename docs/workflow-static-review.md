# 静态代码 review 记录

范围：统一操作/输入输出、运行权限、调度、外部调用、脚本、验收、决策、展示与部署。这里记录实际审查发现及处理；不是用编译检查代替代码 review。

## S1 契约与兼容

- 检查操作参数是否能覆盖动作、URL、密钥、环境、GPU 和素材路径：新 operation 参数按操作允许字段校验，输入单独引用。
- 检查参数 schema 与实际校验是否一致：删除不适用字段和未引用 definitions，运行时/API/CLI 从登记表生成；API读取执行器实际配置快照。
- 保留 local/image 和旧验收 kind；script 为 local 别名；新增参数归一化后仍可再次解析。
- 对话 mode 与 permission_profile 分开，权限由服务端挂载派生，不能由请求指定。

## S2 输入、模型与外部调用

- 检查输入角色、依赖、项目归属、修订、sha256、文件复制和候选歧义：显式绑定已验收结果，多个主候选等待用户选择后复验。
- 修复外部图片服务 Cookie 未跨查询保存的问题，Cookie仅在服务端数据库保存；直接工具代理同样恢复会话。
- 请求意图在 POST 前持久化，提交未知不重提；已确认拒绝与未知区分；同步服务结果保存后可恢复，不伪造任务 ID。
- 模型挂载按操作缩小到必要环境/权重；CUDA 使用已分配 GPU UUID；固定 worker 使用 Python -P，避免工作区模块覆盖固定实现。
- 文生图实测返回尺寸不符合请求：新增明确的 native/contain/cover 策略，不自动裁剪，精确验收要求必须选择显式尺寸处理。
- 图生视频仍缺真实服务，通用 job 协议不能当作已完成接入。

## S3 调度与资源

- 检查无模型配置是否阻塞本地推进/取消：候选过滤只作用于真正 Agent 运行；模型健康与配置状态分开。
- 检查 manual 外部等待是否持续占运行环境：持久化提交/查询/收取阶段，查询间隔不占执行槽。
- GPU 先申请再创建运行环境，不可用时延期；资源等待不消耗恢复次数。CPU/内存登记与实际 cgroup 上限一致。
- 检查队列公平：跨 manual/agent/workflow 统计用户及任务最近调度，而不是每轮固定 manual 优先。
- 恢复后按最新工作流状态重选类型；取消路径不依赖普通业务槽，排空时仍处理取消。
- 实际 GPU 调度测试发现资源计算与执行步骤可能不一致：领取时将 step_id 持久化到执行尝试和租约，运行中继续使用该步骤资源配置。整套回归又发现接管 running/submitting/collecting 步骤时漏绑步骤：先选中断步骤，再进行恢复，定向恢复和调度 14 项测试通过。
- 同用户新任务持续入队时以创建时间作为最后排序依据；项目中其他任务的未完成清理同样阻止领取，避免只检查当前任务。
- SQLite WAL 设置 ACL 存在消失竞态：改为打开文件描述符后操作，新增 WAL 由父目录默认 ACL 保护。
- 同 UID 的特权测试不可并行：测试加互斥并确保清理异常也重置上下文；生产仍使用共享身份池和隔离保护。

## S4 脚本、验收与修复

- preflight 在实际只读沙箱检查语法、依赖和 JSON，绑定脚本/配置/环境清单哈希，明确不执行完整业务。
- 自定义检查器有路径、时间、资源和报告结构限制；signal 不能覆盖基础文件损坏，Agent 内容验收不能绕过技术失败。
- 视频内容证据必须声明 coverage；inconclusive 不能 pass。
- 发现预设修复未使已完成后继失效：改为原子更新依赖链版本，并在最终放行时核对实际输入修订；独立分支保留。
- 自动修复允许本地 argv 或登记的安全本地操作参数，不能改变目标、验收、输入、依赖和权限；已经执行的外部后继需单独授权。
- 最终结论应用后由服务端更新真实交付文案，不能残留“尚未交付”的临时回复。

## S5 用户决定、状态与产物

- quality 与 clarification/selection/external_call/plan_change 分开；外部调用必须有可审阅提案，不能以质量 approve 或 resume 授权。
- 重复、过期、跨项目决定拒绝；候选选择映射到当前产物，而不是重新生成。
- stop 为失败终态；取消/预算/恢复次数耗尽关闭待处理验收请求。
- 业务输出角色、质量状态、最终交付和主展示分别记录，旧展示标记按既有优先级兼容。
- 问题、选项、诊断及参数变化均转义后展示；技术细节折叠。确认界面展示实际执行意图与外部调用次数。

## S6 检查与部署

- 部署脚本检查全部 TODO 状态及整体测试结果，未完成项阻止重启；源代码快照与 SQLite backup 仅 root 可读。
- 先停止接收写入并排空执行，再更新 ACL/镜像/迁移/unit，启动独立 reaper/API/Agent，检查健康。
- 回滚不自动覆盖发布后的用户数据，也不声称磁盘快照能还原更早的内存版本。
- 源码编译、JS/Shell语法、git diff --check 作为附加静态检查；真实模型、真实网关、浏览器和模拟协议的证据分别保存。

## 本次补充：统一生成与供应商适配

- ai-tool 仅参考协议和参数，未复制阻塞轮询或后台任务池；上层使用三个 operation，服务端执行一次 submit/poll/download/cancel。
- 外部调用先写意图，再 POST；新 implementation 列保存协议、模型、地址、参考图哈希，恢复时按原协议路由，旧记录仍按旧 jobs 协议恢复。
- 写实人像参考图被 Seedance 明确拒绝，保留失败记录，复用已生成人物图改用 Wan；没有自动重试收费生成，也未降低内容验收。
- 下载只允许 HTTPS 存储域名，不转发 API key，不跟随跳转；诊断仅保留安全错误代码。原始参考图 base64 不写入调用快照。
- Seedance 真实取消测试返回 InvalidAction.RunningTaskDeletion：运行中不能取消，映射为 unsupported；Wan 未知取消接口不猜测。同步请求取消监视器既有测试再次通过。
- 低权限网关和独立 reaper 按需取得新图生视频凭据，普通沙盒无权访问；清理按保存的供应商地址，防止配置变化后取消错任务。
- 新增文生视频操作不增加调度类别，输入为空；图生视频必须明确唯一 source 引用。输入、状态、服务重启、取消与凭据边界有新增测试。

## 步骤类型收敛：仅 script/operation

- Step.kind 只接受两种值，删除 step.image 字段及 script→local 归一化；for_step 对未知类型明确拒绝。素材和验收 image、执行阶段 local 属于其他维度，不做全局替换。
- 手动异步图片入口统一构造 operation/inputs/parameters，复用原登记与执行器；更新 Agent、运行时能力清单和示例。
- 一次性迁移仅处理确定的步骤结构，覆盖 definition、spec、修订版本、验收决定、用户提案及 manual 异步定义，不修改状态、revision、任务ID或文件。迁移标记与数据同事务，损坏记录导致全部回滚；不在请求解析或执行时兼容旧格式。
- 当前 operation 记录只删除废弃的 image:null 字段，不按当前机器供应商配置重新验证，避免 API 进程没有生成凭据时影响历史记录迁移。
- 图片转换保留源素材和参考图顺序、适用业务参数与验收；不会将 metadata/acceptance 的 kind=image 改成步骤。
- 生产数据库副本演练：2个local步骤转为script，5个JSON文档更新，执行状态、尝试次数、上游ID与产物均保持一致。

- 全量回归暴露测试环境复用生产身份目录：独立reaper根据生产数据库判定测试租约不存在并回收。测试执行器已使用独立的短路径身份目录及UID范围，保留原业务断言；视频合成/时间线定向复测通过。未放宽生产租约或清理机制。

- 部署后的真实队列检查暴露独立reaper的跨尝试清理竞态：旧尝试的清理回执调用任务级request_cleanup，会把同任务新尝试标为pending。新增回归在修复前稳定失败（allocated变pending），修复后通过；mark只更新对应attempt，不触碰新尝试和外部调用。
- 新身份记录原先先公开task_id再写permit_until，存在被watchdog当作过期的窗口；改为同一次原子保存任务与有效许可。真实隔离环境下验证首次发布已有有效许可，恢复及清理7项定向测试通过。
