# 动态工作流真机 case 审查

审查原 77 条，保留全部业务目标；调整 77 条入口/协议断言，新增 22 条通用能力/动态协议 case，共 99 条。没有以简化实现为理由删除业务验收。新增的 S31 与 D21 分别补音轨/静音类型语义和不可变修订闭环；C16、C22 改为验证登记的受控音频与顺序媒体编译能力。

删除的是过时的实现绑定：R 组直接插入旧表的规划夹具、改写既有节点、旧状态名以及 R17 的 Jev 特定分类断言。原始定义仍保存在 cases.json，不作为新版本通过证据。

每例都必须生成浏览器、日志、观测、数据库、缓存、BOSS 与清理审计；真实结果另按原内容检查器验收。当前清单不是执行报告，所有新版本结果初始均为 not_run。

R 组通过真实 Manager 建立 prepare_a / prepare_b / clip，并复用固定修订与哈希。保留原分支重算参数（R05 为 prepare_a 亮度 1.35，R06 将 prepare_a 素材换成 rocket）、视频/封面像素参考、R14 实际输出完成标记以及 R16 三版本交付。R01–R03 的“待确认修改”调整为复用已验收结果后、下一轮授权提交前修改草稿；不再允许改写已经执行的 DAG。独立检查器比较实际已验收输入的像素，不能只看尺寸。

R10/R12必须先完成首次正式交付，R16必须完成V1/V2正式交付后才能进入下一版；`observeTerminal`返回暂停或失败不代表交付。驱动在干预前检查`succeeded`及非空`delivery`，独立检查器再次核对各前序工作流。未触发前置边界保留原始原因，不计为用例通过。

故障边界用例在自然语言目标中明确要求必要的等待窗口、retry_policy 或两轮规划；这些要求仍由真实 Manager 提案并执行，驱动不插入成功状态。未实际触发目标边界按未覆盖报告。
