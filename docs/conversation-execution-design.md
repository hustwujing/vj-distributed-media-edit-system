# 对话执行与持久化优化

## 目标与执行顺序

1. 有效执行意图、语义审核和项目版本共同决定方案就绪；前后端使用相同状态。问候/问答不出现执行卡片，过期、未审核、缺失意图的请求不能执行。
2. 普通消息使用同一 agent 调度类型下的轻量策略。服务端 Responses 请求仅有元数据/历史查询和受控升级工具，无宿主代码执行能力；只有持久化升级请求后的下一次调度才分配沙盒。
3. 有效方案的自然语言确认经 Jev 识别，并在事务内再次校验版本后转为执行；修改、否定、问题、歧义均不能确认旧方案。
4. 重型 Agent 使用精简固定规则和能力索引，按需读取现有参考文档；跨轻重路径以数据库对话和结构化方案承接，不依赖未保存的内存。轻量入口可按需检索当前项目历史原始消息；沙盒内提供由 PostgreSQL 重建的只读 conversation.jsonl，避免精简摘要丢失旧约束。
5. 检查点分离静态运行资源、动态会话和工作成果。排除内置技能、缓存、锁、日志等可重建内容；冻结后一起保存 SQLite 主文件及 WAL；分布式会话状态打包为一个受校验对象，工作区按哈希复用对象。保持原有租约隔离、原子发布与历史恢复。

## 接口与状态

- 新增内部 agent_routes 记录轻量/升级状态、能力、原因、元数据查询记录和所关联的候选方案。属于执行策略，不增加顶层任务类型或对话权限模式。
- 新增 plan_readiness 保存 intent digest、项目状态指纹、语义审核结果和失效原因。只读 public 接口返回 readiness / can_execute。
- 模型提出升级不等于执行授权。inspect / plan / preview 只能以当前 plan 权限进入沙盒；execute 必须经过按钮或自然语言确认的同一服务端门禁。
- 普通文本、明确追问、元数据查询、升级决策以及 Jev 调用均保留调用账本；没有沙盒的任务也受限额、租约、超时和取消约束。
- 模型或 Jev 的不确定输出不触发执行。结构化结果解析失败不按提示词匹配业务内容，也不把用户文字当成宿主命令。

项目元数据区分上传素材与已保存工作文件，提供有界目录和截断提示。生成结果不必重新上传即可申请只读分析；工作文件存在不等于质量已验收，历史记录提供交付依据。

## 模型与成本边界

轻量入口使用现有主模型 gpt-6-astra，一次请求可以直接生成回复或提出工具调用，不额外单独调用一个分类器。元数据/历史查询通常需工具结果后的继续调用；升级到完整 Agent 也有后续模型调用。它减少上下文和沙盒成本，尚未单独配置较小的入口模型。Jev（配置别名 jev-latest）只在存在候选方案时识别确认意图，以及在结构化执行意图提交后审核方案。权限、版本、防重和资源调度由程序决定。

## 验收检查项

- [x] 问候、知识问答：无执行卡片、无沙盒、无检查点上传；计量和流式输出完整。
- [x] 已有元数据查询不分配沙盒；缺失元数据或像素内容分析正确升级。
- [x] 升级跨进程恢复，维持 task/run 关联；不可越权读取素材或升级为 execute。
- [x] 有效方案才显示卡片；无意图、未审核、素材/画布变化、过期方案被执行接口拒绝。
- [x] 自然语言确认、修改、否定、疑问及不明确表达分别处理；确认防重、版本绑定、Jev 不可用时不执行。
- [x] 静态技能不进入新检查点；SQLite/WAL 一致、打包恢复无路径穿越、限额和哈希校验。
- [x] 重启和跨节点恢复、未变化文件复用、历史检查点恢复均通过。
- [x] 完整 Python/前端回归、真实浏览器流程、原 60 案例只读回归与部署后验证通过。
