# 生成与编辑模型的提示组织

先读取本轮实际 operation 的能力：`python /opt/workflow.py capabilities --operation OPERATION_ID`。输入素材、结构化参数和用户已确认要求是依据；没有确认的审美建议不能偷偷变成硬要求。

按需要组织提示，而非机械填满全部项目：

1. 主体与场景：具体对象、身份、数量和环境，保留用户原要求。
2. 动作或编辑目标：明确要发生的变化；不要把主体运动与镜头运动混为一谈。
3. 构图与风格：只写用户指定或已披露确认的选择，不自动加全身、电影感或固定机位。
4. 参考输入职责：原图、首帧、选区指示、风格参考各是什么；纯文本生成不虚构参考图。
5. 必须保留与允许改变：身份、文字、形状、位置、选区、背景等，以已确认方案为准。避免同时要求“完全不动”和改变同一对象。

尺寸、时长、seed、数量、层数用实际参数表达；提示中的文字不能替代工具参数、权限或能力限制。不得为了提示更短省略否定条件、保留要求和具体文字。不能用“确保”“严格”宣称模型已保证生成质量。

## 图片编辑与选区

有选区时，图1为原图，图2为红色选区指示，不应把红色当作品内容。只修改被选区域，保持选区外内容。擦除应说明移除对象与合理背景补全，检查文字笔画及残影。现有服务端还会按原分辨率蒙版合成来保证选区外像素；这项程序保证不能被提示替代。

Qwen编辑每张输入的两边至少256像素，选区指示图占两个参考图名额之一，完整提示（包含服务端边界说明）最多2000字符；以当前 capabilities.constraints 为准。超限时明确缩减非关键描述，不静默截掉用户约束。

SAM3文字选择用简短英文目标名；点、框与文字三种模式互斥。使用点/框时 prompt 为空，不同时发送文字。只要求SAM3而不精修时 parameters.refine=false；这是参数选择，不靠提示词模拟。

## 图生视频与文生视频

图生视频明确 source 是实际首帧。reference_size_policy=match_output 时，先声明本地尺寸准备阶段；裁切/留白需在方案说明，不能假定服务自动扩展参考图。检查人物边界与留白，已经出画的内容不能靠后处理恢复。

camera_motion_control=prompt_only 时，数值缩放描述不代表轨迹保证。需要精确运动，应在已确认计划内考虑生成与确定性后处理分工，并测量实际结果；不能用拉伸、循环或定格掩盖不支持的时长。帧级时长误差按能力提供的 tolerance 验收。

服务端负责真实provider/model、提交、查询、收取和取消；Agent 不自行编写网络循环。提交成功不代表产物通过；检查不合格时保留证据，额外生成须按既有授权流程处理。
