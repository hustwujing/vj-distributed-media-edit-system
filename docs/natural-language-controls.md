# 自然语言任务控制

聊天页面有活动任务时，输入继续提交到
`POST /api/projects/{project_id}/agent/{turn_id}/control`；普通控制不创建新 turn，`replan` 创建关联的新方案轮。
按钮和显式 `action` 不调用模型。固定中文口令优先匹配，新增
“继续 / 继续任务 / 恢复 / 恢复任务”。其他文字由 DiffusionGemma Jev 分类。

模型只接收本条消息及该轮状态，不读取项目素材、历史消息或内部配置。
调用 `/v1/systemone` 的 `choice` 问题，类别固定为
`status / pause / resume / cancel / replan / other`，一次采样、一步解噪、不生成思考文本。
它只给出分类，不能选择其他任务、修改工作流或调用控制函数。

## 配置

设置在 API 服务的环境中（本机部署为 `.env`），不需要修改 Agent 执行器环境。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `VIDEO_USE_CONTROL_INTENT_URL` | `http://127.0.0.1:8011/v1/systemone` | 完整结构化分类端点；空值禁用模型分类 |
| `VIDEO_USE_CONTROL_INTENT_MODEL` | `jev-latest` | 模型名称 |
| `VIDEO_USE_CONTROL_INTENT_API_KEY` | 空 | 可选 Bearer 凭据 |
| `VIDEO_USE_CONTROL_INTENT_TIMEOUT_SECONDS` | `2` | 读取超时，限制在 0.1–5 秒；连接超时另为 0.5 秒 |

不继承进程的 HTTP 代理或 netrc 凭据，不跟随重定向，不自动重试。
每个 API 进程最多同时进行两次分类；连接/响应异常后 15 秒暂缓模型调用。
固定口令和按钮在暂缓期间仍可用。客户端超时并不保证上游停止推理。

## 接受与执行

校验完整类别概率、数值范围、总和及获胜类别。查询最低分为 0.80，
暂停/恢复/取消/重新规划最低分为 0.95，与次高类别至少相差 0.20。
这些是保守的接收阈值，并非经过校准的正确率保证。
`other` 或分数不足返回 409；分类服务不可用、超时或响应无效返回 503。
两种情况均不改变任务，前端保留输入供用户调整或使用按钮。

模型调用前检查项目及 turn 归属；调用期间不持有数据库/项目锁。
执行前重新读取目标 turn 并检查状态，已结束或正在停止的任务不能再变更。
暂停和恢复继续由现有 workflow 状态机校验。`replan` 只接受带修改内容的消息：
服务端在事务内重新核对旧 turn 仍处于活动状态，停止旧 turn，创建一个关联旧 turn 的新
`plan` turn，并保留旧 turn 的素材选择、画布目标和已提交步骤作为只读 continuation。
新轮次须通过队列、规划额度和工作节点检查，并复核画布版本；拒绝时整笔事务回滚，旧任务保持原状态。
新 turn 重新声明执行意图、生成方案并等待确认；旧 turn 的确认不会继承。
分类期间旧 turn 已结束时，不创建新 turn，也不把请求转移到其他任务。同时提供 `message`
和 `action` 时，两者必须一致。

提示词将否定操作、假设、引用、含糊和冲突操作归为 `other`。
例如“不要停止”“如果取消会怎样”“暂停并换个背景”均不应执行控制。
“继续，但把背景换掉”“字幕改黄色”“只停止配乐”“重新做成竖屏”属于 `replan`，会停止旧方案并开始
新的规划轮。`replan` 不直接修改工作流、不直接授权执行，也不保证旧任务的上游外部调用已停止；
旧任务的本地停止和上游停止状态继续单独展示。

## 验证

通过[隔离测试入口](development.md#常规回归)运行 `.venv/bin/python -m tests.run_distributed_suite tests.test_control_intent`。
覆盖真实本地 HTTP 请求格式（模拟 Jev 响应）、概率校验、超时和并发保护、
固定口令、权限、工作流控制、重新规划父子关联、旧任务停止、分类期间任务结束的竞争情况。
模拟响应的测试不证明真实模型对否定、歧义和提示注入的识别准确率。

以下为接入时的历史验收，不代表当前工作区或部署状态。本机检查记录：2026-10-31，服务健康检查返回 200，但共享推理服务
有大量请求积压，观察到请求耗时约 587–594 秒；实际分类探测 20 秒超时。
因此暂未取得真实分类准确率和正常负载下延迟证据。没有重启或修改共享模型服务。
部署前应在模型服务负载正常时验证自然表达、否定、局部修改、歧义及提示注入样例。

本次验证结果：14 项新增测试及 40 项相关回归测试通过，Python/JavaScript 语法检查通过。
使用临时项目对接真实分类服务，请求约 2.018 秒后返回 503 降级提示；
原任务仍为 waiting，随后固定口令“查进度”返回 200。应用代码已修改，未重启线上服务。


重新规划的内容指纹同时读取项目工作区检查点和当前修订的步骤检查点，与 Agent 的恢复视图一致。将既有步骤产物恢复、汇入项目检查点不会被误判为内容变化；当前项目的真实内容或步骤产物哈希变化仍会使待确认方案失效。其他项目的检查点不参与计算。

语义控制分类会读取当前目标任务的已确认方案、步骤目标与修订、最新公开说明和待回答问题，均为有界上下文。历史与待决选项不授予新权限，回答问题不自动变成恢复任务。分类后若方案、步骤修订或待回答问题发生变化，返回冲突并要求刷新；固定按钮及明确口令仍沿用确定性控制路径。具体接线与审核恢复见[方案审核修复](plan-review-recovery.md)。
