## 已确认的设计边界

- Harness 指负责 Agent 循环、工具交互和会话管理的执行框架；模型 Adapter 负责模型服务协议、请求与回执。换 harness 与换模型是两个独立选择，组合须经过兼容性验证。
- 保留 `agent` 调度类型及现有 plan/execute 权限模式；不为每个 harness 新增调度类型，不重新实现 workflow 调度器。
- 通过公开 SDK、事件流及本系统的工具入口，运行时记录统一上下文。跨 harness 交接不依赖解析厂商私有会话存储格式，不假定能够迁移全部内部状态。
- 原生会话状态作为不透明快照保存。同一 harness 的兼容版本恢复时交回该 harness；不把 Codex 会话文件改写成 Claude 或 DeepSeek 的原生格式。
- 数据库中的任务状态、授权、外部提交记录、验收和成果版本是业务权威依据。模型叙述和交接摘要不能覆盖这些记录。
- 模型偶发错误与程序错误分开验收，遵循[程序正确性审查原则](program-correctness-audit.md)。

- [x] C01：运行时从公开接口采集用户消息、公开回复、工具开始/结果/错误、待决问题和成果引用；保留来源、版本、事件游标与覆盖范围。使用现有公开对话、工具、workflow 和成果记录，避免再建相互矛盾的业务状态源。
- [x] C02：定义交接包，包含原始需求与后续约束、当前已确认方案及 digest、关键讨论、执行结果、有效成果修订与哈希、失败诊断、等待事项、预算余量及下一步动作。
- [x] C03：长历史采用摘要与按需检索的原文/工具结果索引；标记截断、缺失和来源，关键用户约束不能只保留无依据摘要。不将私有推理或凭据放入统一公开上下文。
- [x] C04：原生快照采用 harness 标识、适配器/运行时版本、会话格式版本、原生 session ID、配置/工具策略摘要和存储引用组成的外层描述；复用对象存储、归属校验、哈希、版本保留和检查点提交机制。
- [x] C05：由公开会话导出/恢复接口或受支持的会话目录搬运实现原生快照；通用层负责外层文件完整性与安全，不理解内部私有语义。同一 harness 不兼容时创建新会话并加载统一上下文，显式记录恢复方式。
- [x] C06：为历史任务标明上下文覆盖范围。旧记录只有部分事件时不能宣称无损交接；必要信息缺失则保留任务并请求补充，不猜测未记录的工具结果。

## S：切换 Agent 与恢复

- [x] S01：设计持久化切换记录，保存切换 ID、源/目标 harness 与配置、原因、原/新 session、任务/方案版本、检查点、事件游标、阶段和失败原因。重复请求及中断恢复不重复激活接管者。
- [x] S02：在安全边界切换：停止旧 Agent 接收新工作，确认旧执行范围停止或隔离，撤销旧租约写入资格，再提交交接快照并激活新 Agent；旧事件和迟到结果不能覆盖新状态。
- [x] S03：切换前核实未结束的工具及外部调用。提交结果未知时先查询/对账或暂停核实，不重放历史命令，不假定没有提交，也不自动重复付费生成。
- [x] S04：已提交 workflow 按原步骤图继续由调度器管理；已通过成果保留。仅替换后续需要 Agent 的分析、验收和诊断执行者。等待外部任务时不额外占用 Agent 沙盒。
- [x] S05：新会话启动前恢复所需文件并加载交接包；重新从服务端核对项目归属、方案 digest、步骤修订及成果哈希。交接文字不授予权限；同一已确认任务按原授权续接，新增需求或扩大范围仍需原有确认流程。
- [x] S06：区分同 harness 同版本续接、兼容版本恢复、同 harness 换模型、跨 harness 接手和无法恢复。原生恢复失败不能自动解释成可以安全重跑业务。
- [x] S07：切换失败保留原有业务状态与成果；只有确认唯一执行权和恢复兼容性后才能回退，不允许两个 Agent 同时继续任务。取消和租约失效优先于切换。
- [x] S08：用户侧展示当前 harness/model、切换中/已接手/待核实、已保留成果与上下文覆盖缺口；沿原 task/run 关联展示消耗，同时区分不同 harness、模型和 attempt。

1. 定义公共契约、事件和配置档，抽出 Codex 实现并完成现有功能回归。
2. 建立统一上下文记录、原生快照外层描述与预算/计量公共策略。
3. 分别接入 Claude 和 DeepSeek Harness、对应模型协议，验证能力矩阵。
4. 实现切换协调、接管与失败恢复，接入前端及观测。
5. 完成独立测试、整包回归和真实场景；实际实施与部署另行安排。
