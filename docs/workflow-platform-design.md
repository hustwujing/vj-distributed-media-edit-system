## 概念模型

| 维度 | 权威字段 | 取值与职责 |
| --- | --- | --- |
| 调度职责 | dispatch_kind | agent/manual/workflow；沿用数据库 kind |
| 用户阶段 | conversation_mode | plan/execute；不代表实际权限 |
| 权限配置 | permission_profile | planning/execution/review/step/fixed_tool；服务端选择 |
| 业务能力 | operation | 服务端登记的稳定 ID；模型/供应商是实现配置 |
| 步骤实现 | kind | 仅 script/operation；旧存储格式一次性迁移 |
| Agent 目的 | purpose | review/diagnose/final；重新规划使用受控修订/用户决策 |
| 验收 | target/method/reviewer/severity | 文件或输出角色、检查器、程序/Agent/用户、阻断/信号 |
| 状态 | 各对象 status | 不合并不同对象的状态；增加 wait_reason 描述原因 |
| 输出 | role/quality_state/delivery | 业务输出角色、验收状态、最终交付分别表达 |

任务—执行尝试、工作流—步骤—修订、步骤—产物、验收请求—版本快照是不同关系。调度类型由当前持久化状态决定，恢复改变状态后必须重新分派。terminal: succeeded/failed/cancelled；paused 是可恢复阻塞，不代表终止。

## 操作与步骤协议

能力登记提供输入类型、参数模型、输出角色、固定实现、CPU/内存/GPU/外部并发、重试/取消/恢复规则、时限及可用性。Agent 不指定环境路径、密钥、服务地址或 GPU。静态能力文件与运行时 API 同源生成。

新步骤支持 kind=operation、operation=<登记 ID>、parameters、inputs。输入为 asset 引用或 step+role 引用，禁止任意 URL/宿主路径；跨步骤输入必须声明 depends_on，绑定验收通过的修订、sha256 和唯一输出角色。script 使用相同解析后的输入。旧存储记录一次性转换，入口与运行时不接受 local/image 步骤。

优先接入既有图片动作与转写；真正文生图及图生视频采用已核实服务协议，能力不满足时在提交前拒绝，不能用无关图片充当生成输入或循环视频凑时长。

## 规划与入口约束

方案阶段产生机器可读执行意图（single/workflow、操作列表、输出目标），用户确认继承该版本。多阶段或耗时操作强制工作流；独立短操作允许直接工具。直接入口根据已确认意图判断，不能仅检查 workflow 是否已经存在。旧方案缺声明时保守引导补充，不扩大权限。

## 执行器与资源

固定本地工具复用图片/转写执行代码，按能力最小挂载模型目录，普通脚本始终无网络、无凭据、无 GPU 模型环境。输入只读，独立输出目录，真实资源清理成功后释放。

资源预留在领取计算槽前完成；资源不可用时保存 waiting_reason/next_poll，避免等待 GPU 占 CPU 槽。外部异步步骤保存提交意图及 ID，等待期间不占计算槽，外部并发名额持续保留直到完成/确认取消。同步服务没有任务 ID 时不可假称支持查询恢复，采用持久化尝试与提交未知保护。

调度候选包含 manual 和 agent/workflow，按用户最近服务及类别轮转公平选择；取消不依赖模型配置。模型不可用只阻塞真正需要模型的执行，其他推进继续。节点、用户、项目互斥和清理限制保留。工作流独立分支可在外部等待间隔推进，不宣称任意并行。

## 外部调用协议

统一 submit/poll/collect/cancel 适配器；先保存意图，后网络请求，再持久化 ID。记录请求键、供应商、步骤修订、尝试、输入摘要、用量/费用（未知为 null）。上游未证实幂等时提交未知必须阻塞；查询或下载重试不等于重新生成授权。下载大小、类型、地址与项目范围固定。取消记录 pending/complete/unknown/unconfirmed/unsupported，不把本地停止当上游停止。

## 验收、脚本与修复

新验收结构分离目标和执行者，同时兼容旧 kind。补透明度、帧率、完整解码、JSON 字段与字幕时序，警告不伪装成硬通过。受控自定义检查器只读输入，结果结构化。

脚本 preflight 在目标沙箱进行语法/参数/依赖检查，绑定脚本与配置哈希和环境 profile；只做 bounded 小样本，不能触发外部收费调用。提交时持久化完整文件检查点，执行时验证版本。按高价值中间成果拆步，不每条命令拆步。

Agent 验收保持只读，必须给实际证据和覆盖范围。错误分类区分临时、确定性、质量、授权、预算与提交未知。自动修复不降低验收、不扩大外部调用；stop 是终止，needs_user 使用明确用户决策类型。计划变更与外部重生成须明确版本和授权。

## 用户决策与展示

决策请求种类：quality/clarification/selection/external_call/plan_change。绑定工作流、目标修订、选项及允许动作；质量 approve 不能授权外部调用。控制操作 status/cancel/resume/pause，其中暂停在安全边界生效，不能用 resume 重新生成。

UI 展示业务阶段、资源等待原因、验收与修复、用户决策和实际限制；详细日志折叠。业务输出角色、可供下游消费、最终交付和主展示独立。模型无可用服务时明确说明，不伪报成功。

## 兼容、验证与部署

数据库采用增量列/表迁移；旧步骤通过一次性数据迁移收敛；验收规则保留其独立兼容策略，旧任务不自动扩大能力。每个新状态/操作必须覆盖校验、授权、执行、恢复、取消、预算、UI。测试层：纯模型/规则单元测试、SQLite 状态与竞争测试、真实 Linux namespace/Gateway/GPU 固定工具测试、模拟 HTTP 故障测试、真实上游 smoke、完整人物图→视频→图标→合成链路及已有全量回归。

部署前保存代码与 SQLite 一致备份，检查运行中任务；排空 Agent，更新 ACL/工具镜像/systemd unit/数据库，再重启 reaper、API、Agent。检查 health、后台日志、样例任务和资源清理；失败回滚代码与配置，数据库增量兼容恢复。不得覆盖其他已有工作区修改。
