# 动态工作流重构与独立部署记录

基线：`feature/dynamic-plan`，`d818cd8`。产品协议以根目录
[设计草案](../video-use-dynamic-agent-workflow-design.md)为准。用户已授权完成重构、
验证和本机独立部署；不修改或停用 main 实例，不清理其数据。

## 实施顺序与完成门槛

1. 参数化部署身份和本机资源边界，建立独立运行环境。
2. 建立追加式 DAG、授权包络、提案、候选结果及命令模型。
3. 拆分 Orchestrator、调度领取与执行阶段，接入持久化恢复和取消。
4. 接入滚动 Manager、受控专业 Agent 与最终验收。
5. 更新 API、浏览器状态展示、诊断和操作文档。
6. 完成协议及竞争回归、真实数据库/对象存储/沙盒与浏览器验证。
7. 冻结测试版本，部署独立实例，验证 main 未受影响。

## 用户追加的最终验收要求

以下全部属于当前已授权任务，不能以核心流程可运行代替完成：

0. 补齐结构化日志、指标、活动、用量、诊断及告警可观测性。
1. 补充单元/协议/集成测试并运行，报告失败与跳过的具体原因。
2. 审查已有七十多个真机 case，逐条记录保留、修改、移除及理由，并确定新增 case。
3. 更新实际 case 定义和运行驱动，不仅修改清单或报告。
4. 在独立部署上执行调整后的真机 case；逐个从浏览器和日志、观测、数据库、缓存、BOSS
   核对内外状态。程序缺陷持续修复和复测；模型或外部依赖异常按程序的检测、暂停、恢复、
   取消、清理、账本和交付行为验收，不能自动归为程序成功或靠降低验收标准通过。
5. 更新 README 和各级 AGENTS.md / 对应开发规范。
6. 补充新增 harness、专业 Agent Profile 与 LLM 协议/模型的接入开发规范。

真机证据须绑定部署源码摘要、case、运行 ID、浏览器证据及内部状态；区分已通过、
依赖阻塞、模型异常已正确处理、仍存在程序缺陷和未执行。不得把缺证据计为通过。

最终必须交付完整真机 case 测试报告：逐例包含变更分类、步骤、部署版本、浏览器证据、
日志/观测/数据库/Redis/BOSS/资源清理审计、首次失败与修复及复测链路、最终结论。
报告同时提供汇总和可追溯的机器可读证据索引，不能仅提供成功率或截图集合。

不得把仅模型/接口骨架、替身测试或旧版本验收当作全部完成。

## 隔离边界

| 资源 | 新实例要求 |
| --- | --- |
| 源码与依赖 | 本 worktree 的独立环境及冻结发布目录 |
| 进程与账户 | 独立 systemd unit、服务用户、运行时组和 journal namespace |
| 本机资源 | 独立端口、Unix socket、UID 池、cgroup、节点注册和 reaper |
| PostgreSQL | 复用数据库服务，使用独立 database 和业务 role |
| Redis | 独立键前缀；会话密钥与 Cookie 名称独立 |
| BOSS | 独立对象前缀、数据库引用及加密密钥；不修改 main 对象 |
| 文件与观测 | 独立缓存、临时目录、诊断索引、备份和发布记录 |
| 共享只读依赖 | 允许复用解释器、系统工具和模型权重；物理 GPU 继续遵守资源互斥 |
