# 对话执行优化：静态审查与验证记录

## 授权与路由

- 新消息仍是 agent / plan；agent_routes 只记录轻量、升级及执行中的内部策略。轻量路径仅提供项目元数据/原始历史查询和三个受控升级用途，不接受 URL、命令或任意文件路径。
- 元数据查询按项目所有权引用，服务端验证素材 ID。升级先持久化再结束本次租约，下一次调度重新核算资源并创建沙盒，保持同一 task/run。
- 方案必须先有 execution_intent，再由 Jev 审核，最后由服务端以 intent digest、项目素材/画布/正式工作文件指纹确定 can_execute。普通回复成功不产生确认卡片。
- 确认前校验所选素材和画布目标；确认以事务消费方案，绑定 consumed_by，重复点击或旧摘要不能再次执行。自然语言确认复用同一个门禁并合并需求账本。
- 修改需求、撤回、条件句、问答和引用场景不能确认旧方案；分类不确定或服务不可用时保留不执行状态。Jev 语义分数不是确定性授权，最终仍需结构化状态与版本校验。
- 单纯问候不调用 Jev；没有候选意图也不进行方案审核。真实调用均接入现有消耗账本，轻量请求沿用限额、租约和 HTTP 取消监视器。

## 持久化

- 业务数据库仍为 PostgreSQL。会话包中的 SQLite 是 Codex 运行时自己的私有会话文件；测试中的 SQLite 是隔离夹具，两者不替代生产业务数据库。
- 排除内置技能、缓存、日志、共享内存文件、临时锁和可重建配置；SQLite 主文件和 WAL 从冻结状态一起保存，不能单独丢弃 WAL。
- 会话包使用确定性 gzip/tar，验证外层哈希、展开大小、普通文件类型、路径、重复成员及内层清单；不使用不受控 extractall。
- 同项目、仍有引用的不可变对象可按哈希和大小复用。租约校验与原子发布保持不变，跨项目不共享对象引用。
- assets/canvas/workflow/capability/conversation 的只读占位文件在 prepare 时由权威元数据重建，不必持久化空占位。
- 旧格式恢复时先过滤可重建静态内容，新格式通过版本标记识别。版本指针与历史成果仍可恢复。

## 已发现并处理的问题

- 旧接口/测试将任何成功 plan 都视为可执行：改为显式意图和审核状态，并补充直接 API 拒绝用例。
- 原工作区新增 Python 文件没有测试服务账号的读权限：按部署脚本已有规则授予代码读取权限；冻结发布仍执行完整权限准备。
- 恢复清单跨子进程传递不能使用 Python set：改为 JSON 数组。
- 测试持有 SQLite 连接导致测试挂载无法卸载：在清理运行环境前显式关闭测试连接。
- 确定性会话包未变更时可完全复用：更新测试为“初次保存、另一节点不变恢复、第三次变更后仅新增一个对象”，验证真实对象记录而非假定每轮上传。
- Jev 审核条件需要区分“等待用户批准”和“缺失必要参数”；语义规则明确区分制作修改、普通问答及引用场景。真实分类评估覆盖正常方案、问候、擅自提出任务、缺失输入、确认、修改、撤回、疑问、引用和含糊表达。

## 验证范围

完整 Python/前端回归与真实浏览器验收结果见最终报告。实际模型协议探测中，新建项目问候输入约 527 Token、无需沙盒/检查点；这是探测样本，最终延迟以部署后真实测试记录为准。

## 上下文完整性

- 当前用户完整消息和已批准的完整方案保留。轻量入口近期上下文显式标记截断，并提供 owner/project 范围内的原始历史查询；外项目分页 ID 被拒绝。
- 完整 Agent 可读取由业务数据库生成、只读挂载的 conversation.jsonl；它不进入检查点，不把历史内容视为执行授权。失败与取消任务的原始请求及状态也可检索。
- 最后一处界面调整隐藏无工作流的轻量聊天资源预算面板，避免问候显示尚未分配执行资源。

## 部署后实际验收过程

- 浏览器验收脚本最初假定公开 turn 返回内部 plan_id。实际接口未公开该字段，任务已成功但测试断言失败。修正验收方式：读取公开 usage.run_id，并独立查询 PostgreSQL 的 plan_id / consumed_by；复用已完成任务验证，没有重做编辑。
- 实际旋转任务中 Agent 两次误用预检工具参数，记录为失败工具调用；随后在已确认的单阶段本地处理权限内完成旋转、解码和像素校验。下载结果独立逐像素一致。保留失败计数，不将最终成功说成过程中零错误。
- 轻量聊天仍使用主模型 gpt-6-astra；未实现独立的小模型入口。完整 Agent 仍可能多轮调用和读取较长会话，不能把问候 Token/延迟改善推算成所有编辑任务的同等改善。

- 重启后实际检查生成结果时，轻量入口仅列上传素材，错误要求用户重新上传已存在成果。修复为 project_metadata 同时列出当前项目检查点中的已保存工作文件，并提供数量、查询与截断标记；提示词区分上传素材、工作文件和已验收交付。无需把生成结果冒充素材 ID，空素材列表也可申请只读检查。
- 补充端到端工具协议测试，覆盖无上传素材但已有结果的升级、跨项目隔离和预览过滤；实际模型对图片/音频两类已有成果均正确申请 inspect_media。随后重新冻结完整代码、运行全量测试并部署验证。
