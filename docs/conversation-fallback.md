# 轻量对话的通用分析兜底

用户希望轻量入口不能覆盖的项目问题可以交给完整 Agent，而不是停在“工具不支持”。本轮在现有 request_capability 中增加 general_analysis，不增加顶层任务类型或执行权限模式。

## 实现与边界

- 模型可以为需要核实能力、读取项目上下文或综合判断的需求申请 general_analysis；明确缺少用户决策时追问，普通问候/知识问答直接回答。
- 连续四次有效工具查询仍未回答或交接时，程序直接持久化 general_analysis，不进行第五次轻量模型请求。
- 抽取统一 handoff：检查租约、当前 plan/running 状态、项目素材归属、允许能力及参数；事务内从 light 改为 heavy，并将同一任务重新排队。重复交接、已取消任务及失去租约不能重新排队。
- 完整 Agent 获得原始请求、近期上下文和交接原因，核实实际资料后回答、追问或制定待确认方案。原因是分析线索，不代表事实或执行授权。
- 参数错误、未知工具、跨项目素材、服务错误和取消不会触发自动兜底；正式编辑与外部生成继续要求原有确认门禁。
- 日志 conversation.handoff 区分 model_request / light_round_limit，记录 task_id 和 operation；沿用调用账本和 attempt 链路。
- 不用用户文字的关键词匹配业务路由，也不新增每条文本回复的语义复审。模型仍可能直接给出错误文本；新增出口与提示规则不能保证消除所有误判。

## 静态审查

- 升级校验与重新排队置于同一事务，并在事务内验证租约；以 stage=light 和 mode=plan/status=running 条件限制修改。
- 保留 task/run，不重复提交业务任务。轻量阶段没有 TaskRuntime，后续调度仍按完整 Agent 资源需求分配沙盒。
- general_analysis 不消费旧方案，不修改执行权限；后续形成新方案仍由 execution_intent 与就绪审核管理。
- 只接受既有资产 ID 和短原因，不接受命令、服务 URL 或任意执行模式。
- 撤回、版本失效、自然语言确认、取消及无沙盒问候均通过原有测试回归。

## 检查项

- [x] 通用分析能力可持久化交接，保持 plan、task/run，当前租约退出且无沙盒。
- [x] 四轮有效查询耗尽后交接，无第五次轻量请求，调用计数正确。
- [x] 未知工具、非法参数、外项目素材不触发兜底。
- [x] 重复交接和取消不能重新排队。
- [x] 最终冻结版本全量测试与前端测试。
- [x] 实际模型：能力核实、综合调查选择兜底；问候、明确追问留在轻量入口。
- [x] 真实浏览器：通用分析交接后完成回复，无正式执行或错误确认卡片。
- [x] 完整工作区部署与重启后状态、计量持久化核对。
