# 44 个线上示例的真机验收

实际清单来自独立环境 `/api/demos`，必须为 44 项；每轮保存原始 catalogue、其 SHA、部署摘要、模型配置与驱动源码。使用 `tests/live_demo_library.cjs <独立证据目录> [示例 ID 列表或 all]`，并发固定为用户指定的 8。

每例从公开页面 `http://updream-lab.bilibili.co/distributed-agent-sandbox-backend/` 的“聊天编辑”按钮载入真实示例，核对素材和原始提示，不以预生成展示成果充当本次执行结果。模型使用 claude55/high；新任务的交付选项留空，以验证规划提出、显式确认和回填。所有业务、素材、输出和端口仍属于 sandbox-agent 独立环境。

必须验证：方案及关键参数/输入可见、确认前无业务 Task、需要介入时具体问题可见且有可用操作、系统错误明确而非泛化为补充信息、终态成果可预览与下载、哈希匹配、退出重进后状态和成果仍在、SSE 不反复重放、资源清理完成。业务内容另外逐例审查；驱动完成仅标记 `passed_pending_review`，没有审查证据不能算最终通过。

示例卡的 options 也是用户可见参数。载入必须将其与原始 prompt 一同放入可编辑草稿，不能只显示在首页而在规划输入中丢失；驱动逐项核对。检查最终时长、尺寸、输出格式时同时参考这些参数，不能把 Agent 按残缺输入生成并自审通过视为完成示例要求。

catalogue 明确附带的逐词转写还须登记为项目 JSON 输入，注明 source_asset/audio_track，保证动态规划可以显式绑定已有转写。保留工具页使用的转写缓存不等于动态输入已就绪；授权、独立存储、哈希校验与跨节点恢复仍适用，不向沙箱开放任意项目缓存目录。

遇到待决事项，驱动写出 `attention.json` 和页面截图，等待该目录下的 `answer-<decision_id>.json`；无 decision 的系统错误使用 `resolution.json`。测试操作者审查后可通过原授权动作回答、明确授权或停止，不能写数据库伪造状态、结果或批准，也不能用一条通用“继续”掩盖缺失方案/信息。停止项保留首次失败和归因；修复只允许跨示例的通用规则，不允许产品代码按示例 ID 或固定措辞分支。

首次排查可以只选择关联示例，记录未执行项。发现缺陷时暂停新增用例，保留同一冻结版本正在执行的证据；修改后先跑关联回归及失败示例。最终结案必须在同一冻结版本和 catalogue 上完整运行 44 项，逐例给出程序、契约、提示词、用户体验、产物和清理检查结果。模型随机波动或供应商问题单列，不能将未触发、未审查、超时或缺证据计为成功。

进度每两分钟报告：44 总数、已启动、成功、程序失败、契约失败、明确提示词问题、其他失败、待审/待归因、运行中、平均耗时；平均使用已结束 case 的真实耗时。修复/复测轮次与 case 数分开，最终报告提供全部 44 行、问题根因、通用修复提交和最后完整轮证据。
