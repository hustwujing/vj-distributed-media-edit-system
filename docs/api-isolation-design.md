# API 长耗时隔离设计与验收

2026-11-02：用户已明确授权先实施本项优化，再做完整测试、部署和新一轮 60 条真实回归。旧待办中的“仅记录”约定已由本次授权更新。本文随实现和证据维护，不把设计勾选为已经部署。

## 目标与边界

API 等待存储、媒体、数据库、诊断或分类服务时，不占用事件循环及 FastAPI/AnyIO 默认工作线程。每类依赖的执行和排队都有上限；过载快速拒绝，并为健康检查、任务取消保留独立容量。Executor/工作流的执行类型、授权、租约和模型调用协议不改变。

初始代码事实：同步路由使用默认工作线程；SSE 用 `asyncio.to_thread` 读取同步 Redis；上传持有 `mutation_lock` 直至解码及对象上传完成；删除在数据库事务内递归清理目录；示例加载和图片导入也在全局锁内下载、解码、复制和上传。

## 执行结构

1. API 专用执行器按读取、写入、任务控制、文件/存储、媒体、诊断和控制分类分组。每组设置 workers、queue、queue timeout 和 execution timeout。同步路由经异步包装进入对应执行器，仍沿用 FastAPI 参数与权限校验；明确需要多阶段处理的路由改为异步编排。
2. 上传等请求在解析大请求体前进行有界准入；其他请求的准入不依赖媒体或存储空闲。健康检查保持短异步路径。
3. 排队取消移除尚未执行的工作。执行中的同步 SDK 无法立即终止时，调用方可停止等待，但真实执行结束前不释放执行槽，也不误报“未执行”。未开始、结果未知和明确失败分别响应。
4. Redis SSE 使用 `redis.asyncio`；按连接生命周期关闭客户端与连接池，保留数据库事件、重连游标、回退及退避。数据库快照进入独立读取池，不使用默认线程池。
5. 上传/图片导入先校验并在私有临时目录准备文件，媒体检查与对象上传在锁外完成；提交时用短事务重新校验归属、项目存在、素材限制、版本及存储额度。迟到或取消的结果不得发布。复用现有不可变对象、上传预留与垃圾回收机制。
6. 删除在事务内检查任务/租约/清理并撤销引用，提交后再清理本地目录。示例导入逐阶段执行耗时工作，不能持全局锁阻塞其他项目；失败清理已创建的临时成果。
7. 显式取消不依赖模型服务。自然语言控制先读取目标，锁外分类，再在事务内重新核对目标状态。方案检查的失败与超时不能放宽确认门禁。

本期不改写 Media Service 的 FD-only 安全协议，不新增业务调度类型，不将数据库单连接描述为可并发多路复用。长期持久连接协议依据本期压力测试结果决定。

## 可观测性

池名称为固定低基数集合。记录 active、queued、capacity、rejected、queue_timeout、execution_timeout、cancelled、completed、wait_seconds 和 run_seconds，以及 API 事件循环延迟。关联已有 request/trace/release 字段；不记录 URL 参数、用户文字、文件名、对象 key 或凭据。发布结构化事件与受保护运维指标，异常响应返回稳定错误码、查询编号和适当的 Retry-After。

队列满不创建后台工作；执行超时不提前回收真实线程或伪造远端停止。指标发布必须有界，观察系统故障不能阻塞业务。

## 2026-11-02 阶段证据（非发布完成报告）

- 真实双 API 进程 + Nginx least_conn + PostgreSQL + Redis + 加密 HTTP S3 测试服务，逐一同时阻塞两实例的存储、媒体、诊断、控制分类、普通读取。每池测试容量 1 个执行 + 1 个排队，各实例同时发起 5 个请求；过载返回关联查询编号和 Retry-After，未提前释放真实工作槽。健康/显式取消的最大延迟分别约 170/179/185/188/190 毫秒（单次隔离环境观测，不是生产 SLA）。默认 AnyIO 工作线程在依赖阻塞期间占用为 0。
- 真实 PostgreSQL 表锁使 API 归属查询超时，返回 503 且不泄露数据；基础健康仍可用。解除锁后恢复。递归删除被阻塞时逻辑删除已提交，返回 cleanup_pending，其他项目写入可继续，解除阻塞后物理目录被回收。
- 新增真实 Unix Socket 取消/期限/超大响应测试：本端 FD、Socket 与真实线程最终回收，未声称远端解码被取消。修复超过 32 MiB 输出原本可能被截断后仍成功返回的问题。
- 图片导入期间来源失效、项目删除、调用方取消均不发布；示例导入不覆盖并发用户草稿；整请求期限到达后不发布迟到素材；维护清理保留有效项目，数据库不明时不清除项目缓存。
- 修复项目详情依赖本节点转写缓存的问题：共享模式从已提交的对象引用判断转写音轨，原节点丢失后另一 API 无需先下载转写即可正确显示。
- 取消/超时的槽位保留、原生异步 Redis 连接关闭及数据库回退、上传额度竞争、DB 提交前后取消、事务回滚不发布通知均有定向测试。
- 观测指标白名单、数值范围、去重、乱序、未来时间戳、快照完整性、实际池占用与默认线程占用已测试。快照时效与受保护页面随后纳入整合验证。

测试模块：`test_api_execution`、`test_api_isolation`、`test_api_stream_async`、`test_api_upload_races`、`test_api_media_cancellation`、`test_api_capacity`、`test_api_pressure`、`test_api_publication_races`，并回归媒体、分布式文件、示例、字幕、图片工作台和观测。完整检查以前述 A17/A18 最终证据为准；已通过定向测试不能替代全部 60 条真实业务场景。

短 I/O 边界：框架静态文件响应和有界 multipart 暂存仍可能短暂使用默认线程；被隔离的是同步依赖等待和大处理链路。远端未引用对象沿用现有过期回收机制，本地 API 维护任务不冒充远端自动 GC。上传完成后、客户端收不到响应时结果可能已经提交，响应和诊断需先确认事实再重试。

## 浏览器异常路径补充

真实 Chromium 经隔离 Nginx 访问两个 API，给草稿保存注入 503，同时用 12 个缩略图请求制造媒体拥塞。发现并修复初始化保存草稿失败导致整页被替换、异步刷新继续访问已移除 DOM 的通用缺陷。修改后仍保留项目、素材、任务过程与取消按钮，显示草稿未保存提示；实际点击停止后任务成为 cancelled，页面无 JavaScript 异常。两次修复后的浏览器取消展示耗时约 309/821 毫秒，均为隔离环境观测，不承诺生产延迟。

受保护观测页实际读取两个 API 进程输出的完整容量快照，显示 22 个池、两个循环和全部准入状态；没有用手写假指标替代采集。回归入口为 `tests/run_api_browser_isolation.py`（使用 `VU_API_BROWSER_OUTPUT` 设置截图/报告目录）；使用真实浏览器与隔离 PG/S3/Redis/Nginx，不访问付费模型。测试代理补齐 Host 转发，生产跨站检查保持原规则。

44 项示例补充证据：使用当前实际目录，逐项导入独立 PostgreSQL/加密 HTTP S3 环境，移除 API A 的项目缓存，再由 API B 读取项目和每份素材，44/44 通过。该验证不执行示例中的编辑或付费模型，不能替代 60 条业务 case。原始报告：`/data2/wujing03/vj-api-isolation-demos44/report.json`。

## 真实客户端断连补充

新增真实 HTTP Socket 上传断连回归，修复 Uvicorn 普通请求不会自动取消端点协程的问题。请求体解析后监听断连，取消等待中的业务协程；暂存清理受到保护，已提交结果不因断连删除，真实底层调用结束前仍保留执行槽位。SSE 声明 StreamingResponse 并保持自身连接生命周期，避免两个消费者竞争接收通道。没有请求体的普通端点先收完空 ASGI 请求帧，再监听断开；对不受该端点支持的非空请求体不额外进行无界读取，仍受原有池期限约束。

旧 SSE 测试替身已改为异步接口并断言关闭被等待，保留原有“终态正文补齐、数据库回退”断言。修复过程中分别验证了真实上传断连、SSE 接收通道竞争、取消时暂存清理不被再次取消，以及双实例过载恢复；35 项关联测试通过后纳入扩大回归。完整发布门禁重新运行，不使用此前两份 593 项中旧替身报错的报告作为通过依据。
