# 任务消耗账本设计与验收

本轮目标：按任务及一次需求查看真实调用与返回用量；配额计数继续独立负责限额，不冒充消耗。

## 数据与边界

- `usage_tasks`：task → project/run/parent。新请求建立 run；确认执行继承 plan；继续讨论由客户端明确传 parent_task_id，服务端校验同项目。旧记录仅按明确 plan_id 关联，禁止按文本合并。
- `usage_calls`：每次主模型 HTTP 请求、Agent 工具调用、真正启动的工作流步骤一条记录。call_id 唯一，绑定 attempt/step/revision；重复回执不得累计，终态不得被迟到的开始事件覆盖。
- 上游生成提交及轮询继续以已有 workflow_provider_calls 为权威数据，不维护第二份累计值。提供者回执仅导出数字用量和明确币种的费用，不暴露参数、凭据、签名 URL。
- Responses JSON/SSE 在服务端网关旁路解析；不保存模型内容。input/output/total、cached/reasoning 分别记录，后两项为子集；缺少字段保留 null。已收到的失败/取消回执也保留用量。
- 主模型发请求前落盘；进程消失可通过 attempt 终态识别未完成调用。迟到回执只能更新已有账本记录，不能发布结果或恢复任务。
- workflow 重试＝同一步骤、同 revision 的额外启动；repair_count 单列，轮询、恢复调度和控制任务不计为重试。模型内部自动重试若无明确关联，不猜测其次数。
- 历史 quota、事件、provider 记录可作为原有证据展示；历史主模型 Token 无法补造。汇总覆盖全量记录，详情分页。
- 本轮以实际调用、Token、外部回执及运行耗时为范围。没有硬件实测的 CPU/GPU 时间、显存、费用显示未采集，不以槽位占用时间替代。实时 Token 在最终用量回执到达前为未知。

## 实现步骤

1. 建表、run 关联、幂等调用记录、汇总与安全分页。
2. 接入网关流式/普通响应、工具事件、工作流真实启动；查询已有提供者账本。
3. 同项目授权的任务/run API、对话与工具面板展示、诊断导出。
4. 静态 review、协议/取消/恢复/幂等/分布式/权限单测和功能测试。
5. 实际部署模型任务与浏览器验收，核对 API、数据库、日志；完整回归、报告。

## 检查项

- [x] 新需求隔离，plan→execute 和显式继续正确归组；跨项目不能绑定/读取。
- [x] JSON、任意字节分段 SSE、重复终止事件、失败响应、断流、缺失/非法 usage 均不误计。
- [x] 并发/重复回执幂等，旧事件不覆盖终态；取消后回执只补充消耗。
- [x] 工具开始/完成只算一次，workflow 重试和 revision 修复分离，轮询不算新生成。
- [x] 历史及无回执显示缺口；配额与实际调用分开；汇总不受详情分页限制。
- [x] UI 有任务/run 切换、展开明细、刷新和错误处理；手动任务也能查看。
- [x] 数据导出无 prompt、响应内容、凭据及私有 URL。
- [x] 实际模型请求获得 Token 回执，浏览器显示与数据库一致；真实取消与重启后记录保留。
- [x] 整体 Python/前端测试通过，部署健康，完整报告记录真实测试证据与未测边界。
