# 模型回复协议对照：第一轮结论

2026-11-04。模型为GPT-5.6、Claude-4.6-Sonnet和DeepSeek-V4.1-Flash，均请求high；不同厂商的high不代表相同算力。完整数据、分组、耗时及方法边界见[测试报告](model-reply-correctness-report.md)和[逐试次CSV](model-reply-correctness-trials.csv)。

## 执行结果

正式864次全部结束：549次提案契约合法、283次回复最终未通过、32次模型调用异常；没有待判定或评测器异常。主比较319个及拆分实验230个合规结果均通过独立身份审计，未发现历史Task身份复用或素材范围越界。这是多个有意对照的协议组合总计，不能当作某个生产配置的成功率，更不能算作119条媒体真机验收。

主对照每组90次：GPT旧协议79次合法，新协议strict优先57次；Claude分别12和81；DeepSeek分别7和83。主对照使用30个冻结请求，拆分实验只使用其中12个开发请求；不能直接拿两种样本集的百分比归因。原始业务目标、素材、授权范围、验收和历史未改变，修正后的拆分夹具只重绑定评测代码的策略摘要及snapshot摘要。

## 已有证据支持的判断

1. **接口设计是明确影响因素。** Claude和DeepSeek旧协议大量返回裸ManagerResult或错误动作封装；新命令协议显著提高本轮契约合法率。不能从旧协议表现直接断言模型能力退化。
2. **GPT不能只用超时解释退步。** 新旧主对照分别20和2次调用异常；排除任一侧调用异常后，配对结果仍有9组仅旧协议合法、4组仅新协议合法。结构、语义与调用稳定性均需继续改善。
3. **直接关闭strict不是通用解决方案。** 在同批次、同样本、首次提示相同的36次拆分对照中，GPT非strict首次合法9次，strict优先首次合法25次；前者无首次调用异常，后者有3次。完整试次的最终合法数分别24和27，但纠错反馈不同，不能把最终差异全部归因于strict。
4. **网关接受strict不等于约束生效。** 本轮Claude和DeepSeek在strict请求下均出现违反传输Schema的返回；本地拒绝该动作，并在后续纠错中回退非strict。正式主对照分别记录9和14次此类回退。不能把HTTP 200当作结构保证。
5. **提案生成可用不等于生产接入完成。** 先前Claude-4.6/DS4.1计数接口返回404；Claude原生工具响应还存在实际有输出但output_tokens=0的回执。预算链路不能绕过，成本不能用缺失或可疑回执推断。

## 本轮发现并修复的工程问题

- Responses非strict请求原先仅省略strict字段，上游仍可能自动启用严格约束。41c82b2改为显式false；真实请求回显false，37项定向回归通过。依据：[官方函数调用默认值](https://developers.openai.com/api/docs/guides/function-calling)。
- 协议改动改变harness指纹后，复制的评测夹具仍携带旧策略摘要，造成误判重新授权。40191a9增加显式夹具重绑定及启动前校验；3项回归证明目标、权限、预算和验收事实不变，过期绑定在调用模型前被拒绝。
- 最早14个拆分试次因strict标志问题归档，随后50个试次因夹具绑定错误归档。全部原始结果保留，均不计模型失败，也不进入864次正式统计。
- 协议应用版本15066528b3a6完整门禁通过874项Python（6项显式GPU/OCR跳过）及56项Node。后续7639944c1344增加评测夹具门禁和测试；未据此宣称已部署或通过媒体真机。

## 后续通用改进候选

以下依据字段和业务约束归类，不针对某个case写特殊逻辑，尚未实施：

- InputRef按素材、上游输出和修复候选拆成互斥结构，减少无关可空字段。区分服务端必须执行的约束与严格传输格式引入的重复字段负担。
- 将可用专业Agent、报告产物契约、文件名范围及证据采集资格更直接地表达进模型Schema；服务端仍独立校验，不能因此扩大权限。
- 从冻结状态提供可再次审查的候选和已接受证据，避免模型引用其他revision或尚未完成的证据。
- 对重新授权中必须保持的原目标等数据，评估由宿主绑定或派生，减少模型重复抄写；新增目标仍走明确的新Run协议。
- 分析GPT请求延迟与Schema复杂度、网关路由及模型的关系。超时不应被误判为strict不支持，也不能靠无限重试掩盖。
