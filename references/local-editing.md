# 常用本地音视频编辑

本模块沿用 video-use 的「分析素材 → 讨论并确认 → 执行 → 检查 → 迭代 → 记录」流程。
Agent 决定剪哪些内容和采用什么效果；`helpers/edit_media.py` 执行确定的 JSON 计划。
脚本只使用本机 FFmpeg、FFprobe、Pillow 和字体，不调用模型、不联网、不自动转写。

## 什么时候使用

| 需求 | 计划字段 |
| --- | --- |
| 截取、重新排序、硬切拼接 | `clips`，默认 `layout: sequence` |
| 按对白文字保留片段 | `transcripts` + 每段 `words: [首词索引, 末词索引]` |
| 整段／分段变速，保持声音音调 | 每段 `speed`；不同速度拆成多段 |
| 倒放、片尾定格、循环 | `reverse`、`freeze_end`、`repeat` |
| 裁剪、旋转、镜像、去黑边 | `crop`、`rotate`、`flip`；先观察素材再决定裁剪区域 |
| 横竖屏转换，留黑边／裁满／模糊背景 | `output.width/height` + `fit` |
| 左右分屏、上下分屏、四宫格 | `layout` + `split_audio` |
| 叠化、擦除、滑动、黑场转场 | `transition`，音频同步交叉淡化 |
| 固定区域马赛克、模糊、黑色遮挡 | `masks`，位置是最终输出画布坐标 |
| 中文标题、不同时间段说明文字 | `titles`，自动按画布宽度换行 |
| 字幕字体大小／颜色／位置，逐词高亮 | `subtitles`；逐词高亮必须有缓存词时间戳 |
| 提取／剪辑音频，输出 WAV、MP3、M4A | `output.audio_only: true` + `format` |
| 更换原声、配乐混音、音乐自动压低 | `audio.source`、`mode`、`duck` |
| 音频延迟、循环、音量和首尾淡化 | `audio.offset/loop/volume/fade_in/fade_out` |
| 持续底噪削减、低频过滤、响度归一化 | `audio.denoise/highpass/normalize`，需要试听判断失真；归一化目标为 -16 LUFS |
| 轻微增强、自然通透、暖调 | 每段 `grade`，复用原 `grade.py` |

原 `render.py` 的 EDL 继续可用。这里是独立的 `version: 1` 本地编辑计划，不能把旧 EDL 直接传给新脚本。
时间线分析继续用 `timeline_view.py`，转写整理继续用 `pack_transcripts.py`，自动调色诊断继续用 `grade.py`。

## 调用方式

辅助脚本路径相对于 `SKILL.md`。网页沙箱中为 `/opt/video-use/helpers/edit_media.py`。
当前 cwd 是本项目的独立工作区，`assets.json` 包含素材真实路径及转写缓存路径。
从清单引用素材；不要猜服务器路径、其他项目路径或素材编号。

```bash
python /opt/video-use/helpers/edit_media.py capabilities
python /opt/video-use/helpers/edit_media.py validate edit/plan.json --workspace .
python /opt/video-use/helpers/edit_media.py render edit/plan.json --workspace . -o edit/final-v1.mp4
```

命令行独立使用时，把脚本路径换成仓库 `helpers/edit_media.py`；`--workspace` 指向用户的素材工作区。
计划、素材、缓存和字幕均须位于该工作区内；相对路径始终相对于工作区，**不是相对于 JSON 文件**。
输出只能位于工作区 `edit/`。不得覆盖输入；已有输出或同名报告、字幕、检查图会被拒绝，迭代用新文件名。
讨论阶段可阅读能力、素材、已有计划；用户要求先看样式时，按 [style-previews.md](style-previews.md) 生成并发送静态预览。用户确认后再保存正式剪辑计划并执行视频渲染。

`validate` 只读取文件并探测素材，返回预计时长、每段源范围、输出起点和输出规格；不会产生视频。
`render` 输出逐行 JSON 进度，包括当前步骤、实际编码到的时间、完成或错误。最终返回结果清单。
调用方必须检查退出码；`stage: error` 不是成功交付。

## 制作顺序与同步

1. 从词边界/静音确定剪切范围；有缓存就传 `transcripts`。`words` 索引只统计 `type: word` 项，两端均包含。
2. 每段先提取、裁剪/旋转、变速/倒放、调色、适配画幅；声音用同一段时间和速度，30ms 切点淡化。
3. 硬切用中间文件 `-c copy` 拼接。转场需要重新合成画面并对声音交叉淡化；分屏同时合成指定视图。
4. 完成混音，再处理最终画布上的遮挡和标题；字幕最后烧录，避免被其他叠加盖住。
5. 检查时长、尺寸、音轨和首/中/尾帧能否解码；生成报告及检查图。
6. Agent 实际查看图片，对重要切点/转场另外抽帧，试听声音后才能交付。自动报告仅代表列出的机器检查通过。

变速后每段时长为 `(end-start)/speed`，视频对齐到输出帧；`freeze_end` 追加静止画面与静音，`repeat` 重复整个处理后的片段。
硬切输出时长为各段时长之和；有转场时减去 `(片段数-1) × 转场时长`。
转场发生在不同 `clips` 之间，`repeat` 内部仍是硬切。
分屏以最短视图结束，声音取 `split_audio` 指定视图，之后仍可配乐或替换。

缓存字幕按 `输出段起点 + (词时间 - 源段起点)/speed` 重排，并处理重复与转场重叠。
输入 SRT 必须已经使用**输出时间线**；可以事先人工/Agent 编辑为双语，但脚本本身不翻译。
倒放不能自动使用正向转写字幕；改用输出时间线 SRT，或不添加字幕。

## 结果与迭代

以 `edit/final-v1.mp4` 为例，成功后一起生成：

- `final-v1.mp4`：视频；音频模式则按所选格式输出。
- `final-v1.report.json`：预计/实际时长、输出尺寸、音轨、已完成检查。混音/替换外部音频时还包含 `audio_audit`：同次渲染中实际分支的原声、配乐原始/增益后/duck 后电平、250ms 窗口、来源及输出 SHA。先查看这些程序测量，再决定是否需要补证；长音频的窗口列表会明确截断，汇总仍覆盖全部样本。分轨在 master 处理之前测量，报告明确标注全片淡入淡出、归一化和限幅的适用范围，不能把这些数据当成听感或声音事件语义的证明。
- `final-v1.verify_0.jpg`、`verify_1.jpg`、`verify_2.jpg`：首、中、尾检查图，仅视频。
- `final-v1.srt`、`final-v1.ass`：启用字幕时的时间线文本与样式文件。

临时中间文件只放在 `edit/` 内隐藏目录，默认成功和失败都会清理；排错可用 `--keep-work`。
产出检查通过后才发布结果；不要将隐藏临时文件当作成片。
将实际方案、参数取舍、检查结论和待办追加到 `edit/project.md`，保留历史。

在网页 Agent 的正式执行轮，另写 `edit/deliverables.json` 标明交付文件，例如 `{"primary":"final-v5.mp4","files":["final-v5.mp4"]}`。文件名相对于 `edit/`；优先选用户本轮要求的成片。系统不会再自动把未修改的旧版本全部重复导出；若用户要求重新交付旧版，更新声明并明确指向它。网页将主结果置顶，旧版本仍可从历史结果或原聊天记录访问。

## 明确边界

- 这是传统信号处理。没有人声分离、人物抠像、目标自动跟踪、声音克隆或生成式补帧。
- 慢放按现有帧率采样，不生成新的运动细节。`speed` 是每段恒定速度，不是连续速度曲线。
- 马赛克/模糊遮挡的是固定矩形，不自动跟随人脸；矩形应覆盖目标在指定时段的运动范围。
- 普通模糊不能保证不可识别；敏感信息优先使用黑色遮挡并逐帧检查范围。
- 倒放会缓存在内存里，每段最多 60 秒；长素材先分段。默认倒放画面静音，显式 `reverse_audio` 才倒放声音。
- 总输出最长 1 小时、最多 100 段；网页 Agent 每轮仍受服务自己的时间和资源限制，先做短预览。
- 转写来自已有缓存。无缓存且需求仅涉及画面/音量时，不需要新转写；需要逐词剪辑/高亮时才按原 Skill 流程处理。

完整字段、范围和可复制方案见 [edit-plan.md](edit-plan.md)。
